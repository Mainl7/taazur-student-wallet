# جاهزية تشغيل تآزر على Railway

هذا الملف مختصر عملي قبل اعتماد النظام ببيانات حقيقية.

## 1. بيئتان بدل بيئة واحدة

أنشئ بيئة إضافية في Railway باسم `staging`.

- `production`: للبيانات الحقيقية فقط.
- `staging`: لتجربة أي تعديل قبل نشره للمدارس والمقاصف.

انسخ الخدمات نفسها في البيئة التجريبية، لكن استخدم قاعدة بيانات منفصلة حتى لا تختلط بيانات التجربة مع التشغيل الحقيقي.

## 2. النسخ الاحتياطي

يوجد خياران:

- من داخل الموقع: صفحة `صحة النظام` ثم زر `تنزيل نسخة JSON`.
- من السيرفر/مهمة مجدولة: شغّل داخل مجلد `backend`:

```bash
npm run backup:json
```

قبل أي استيراد كبير أو تعديل حساس، نزّل نسخة احتياطية أولًا.

## 3. متغيرات الإنتاج المهمة

تأكد أن هذه المتغيرات مضبوطة في Railway:

```env
NODE_ENV=production
COOKIE_SECURE=true
WEB_ORIGIN=https://taazur.up.railway.app
JWT_SECRET=<قيمة طويلة وعشوائية>
OFFICIAL_ADMIN_EMAIL=<بريد المدير الرسمي>
SESSION_DURATION_HOURS=8
```

إذا ربطت دومين رسمي مثل `app.taazur.org`، غيّر `WEB_ORIGIN` إلى الرابط الرسمي.

## 4. قاعدة البيانات

- استخدم MySQL منفصلة للإنتاج.
- لا تستخدم بيانات تجريبية في production.
- لا تشارك رابط `DATABASE_URL` أو كلمة مرور قاعدة البيانات.

## 5. فحص ما قبل التشغيل

من صفحة `صحة النظام` تأكد من:

- اتصال قاعدة البيانات.
- عدم وجود حسابات تجريبية نشطة.
- عدم وجود أخطاء مفتوحة.
- وجود نسخة احتياطية حديثة.
- أن `WEB_ORIGIN` مضبوط.
- أن `COOKIE_SECURE` مفعّل.

## 6. بعد كل نشر

بعد كل تحديث:

1. جرّب تسجيل دخول المدير.
2. جرّب إضافة طالب تجريبي في staging فقط.
3. جرّب بطاقة QR وخصم مبلغ بسيط.
4. جرّب الاسترجاع.
5. جرّب التصدير.
6. راجع صفحة `صحة النظام` للتأكد من عدم وجود أخطاء.
